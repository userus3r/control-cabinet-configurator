# Схема базы сравнения цен

Используется одна SQLite-база для всех четырёх типов шкафов. Это позволяет не дублировать комплектующие, которые входят в несколько шкафов, и сравнивать предложения обоих магазинов в одном месте.

## Таблицы

- `cabinets` — четыре конфигурации шкафов.
- `components` — уникальный справочник комплектующих.
- `cabinet_components` — состав каждого шкафа и количество каждой позиции.
- `suppliers` — RS24 и второй магазин.
- `supplier_products` — товарная карточка на конкретном сайте.
- `component_product_matches` — связь карточек магазинов с комплектующими; позволяет вручную подтвердить соответствие артикулов.
- `price_snapshots` — ежедневная цена, наличие и остаток, если магазин их показывает.

## Обновление

Парсер должен добавлять наблюдения в `price_snapshots`, не перезаписывая старые цены. `captured_at` хранится в ISO 8601; для ежедневного запуска достаточно одного снимка на товар в сутки. Цены и наличие следует брать только со страниц, доступных обычному посетителю; обход CAPTCHA, авторизации или технических ограничений сайта в схему сбора не закладывается.

## Инициализация

Применить файл `schema.sql` к новой базе, например:

```sh
sqlite3 prices.sqlite < schema.sql
```

Затем заполнить шкафы и комплектующие в `cabinets`, `components` и `cabinet_components`. Для каждой карточки магазина записать строку в `supplier_products`, связать её с компонентом через `component_product_matches`, после чего ежедневный сбор сможет добавлять снимки в `price_snapshots`.

## Что нужно для настройки парсеров

1. Названия четырёх типов шкафов и перечень комплектующих для каждого: название, артикул/производитель, количество и единица измерения.
2. URL второго магазина.
3. Несколько примеров товарных страниц RS24 и второго магазина. Важно знать, отображаются ли цены без входа и зависят ли они от региона или аккаунта.
